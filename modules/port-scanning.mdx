The Port Scanning module (menu option **3**) integrates Nmap directly into the WSTG-Scan workflow. It extracts the hostname from the target URL, executes a service-version scan (`nmap -sV`), parses the XML output for complete port metadata, displays a colour-coded results table, and then immediately follows up with a targeted NSE script scan — running the `default,vuln,safe` script sets against only the ports that are actually open. Every open port is recorded in the global `FINDINGS` list with a `[PORT]` prefix so it appears in all report formats.

## Two-Phase Scan Design

The module runs in two consecutive phases so that the slower NSE scripts only touch ports that are confirmed to exist, reducing noise and runtime significantly:

<Steps>
  <Step title="Phase 1 — Service Version Scan (nmap -sV)">
    WSTG-Scan extracts the hostname from the target URL (e.g. `example.com` from `https://example.com/path`) and runs:

    ```bash
    nmap -sV -oX - <host>
    ```

    The `-oX -` flag writes XML output to stdout, which is captured and parsed in memory — no temporary files required. The scan runs with a **1800-second timeout** and can be interrupted at any time with **Ctrl+C**, which triggers a clean shutdown that preserves any partial results already collected.
  </Step>
  <Step title="Phase 2 — Targeted NSE Script Scan">
    After Phase 1 completes, a second Nmap invocation targets only the open ports discovered in Phase 1:

    ```bash
    nmap -sV --script default,vuln,safe -p <port-spec> -oX - <host>
    ```

    The port specification is built automatically from the Phase 1 results (e.g. `-p 22,80,443` for TCP-only, or `-p T:22,80,U:161` when UDP ports are present). If UDP ports were found in Phase 1, `-sU` is added to the NSE command. This targeted approach avoids wasting time on the full port range and limits the attack surface for the `vuln` script category.
  </Step>
</Steps>

## Auto-Installation of Nmap

If `nmap` is not found in `$PATH`, the scanner prompts before aborting:

```text
[!] nmap no está instalado.
[?] ¿Instalar nmap automáticamente? (requiere sudo) [s/N]:
```

Answering `s` executes:

```bash
sudo apt-get install -y nmap
```

After installation the scan proceeds without restarting the tool. Declining the prompt skips the port scanning phase entirely and returns to the main menu.

## XML Output Parsing

WSTG-Scan parses Nmap's XML output using Python's `xml.etree.ElementTree`. The following fields are extracted for each port where `state` is `open` or `open|filtered`:

| XML Field | Description |
|---|---|
| `portid` | Port number |
| `protocol` | `tcp` or `udp` |
| `state` | `open` or `open|filtered` |
| `service name` | Service name (e.g. `http`, `ssh`) |
| `service product` | Product name (e.g. `OpenSSH`) |
| `service version` | Version string (e.g. `8.9p1`) |
| `service extrainfo` | Additional banner info (e.g. `Ubuntu Linux; protocol 2.0`) |

Ports are sorted by port number and protocol before display. The combined `product + version + extrainfo` string is shown in the **VERSION** column, truncated to 60 characters if necessary.

## NSE Script Scan Details

The NSE phase runs three script categories simultaneously:

| Script Category | Purpose |
|---|---|
| `default` | Standard scripts enabled by default — banner grabbing, auth detection, common enumeration |
| `vuln` | Known vulnerability checks (CVE probes, outdated software detection) |
| `safe` | Scripts that do not risk crashing the target service |

If the session is authenticated, HTTP-aware NSE scripts receive the active session cookies and `User-Agent` via `--script-args`:

```bash
--script-args "http.useragent=<ua>,http.cookie=<session-cookie>"
```

NSE results are displayed in a second table after the port table. Findings that contain keywords like `vulnerable`, `CVE-`, `exploit`, `backdoor`, `XSS`, or `SQL injection` in their output are highlighted in red and automatically added to `FINDINGS` with the `[NMAP:NSE]` prefix.

## FINDINGS Integration

Every open port discovered in Phase 1 is appended to the global `FINDINGS` list:

```text
[PORT] 10.10.11.45:22/tcp ssh (OpenSSH 8.9p1)
[PORT] 10.10.11.45:80/tcp http (Apache httpd 2.4.52)
[PORT] 10.10.11.45:443/tcp https
```

NSE findings that match the "interesting" heuristic are also recorded:

```text
[NMAP:NSE] 10.10.11.45:443/tcp https ssl-ccs-injection - state: VULNERABLE
```

These entries appear in the **Hallazgos** (Findings) section of every report format — TXT, JSON, Markdown, and the HTML dashboard.

<Warning>
  The `vuln` NSE category sends active exploit-like probes. Only run this module against targets you are explicitly authorised to test. The NSE scan timeout is 2400 seconds for hosts with many services.
</Warning>

<Tip>
  Press **Ctrl+C** at any time to interrupt the scan cleanly. The scanner will wait up to 5 seconds for Nmap to flush its XML output before terminating the process, so partial results are preserved in `SCAN_DATA` and written to the report.
</Tip>
